# 更新日志

[English](release-notes.md) | 中文

每个正式版本在本仓库有一份手写的 `release-notes/<版本>.json`，它是该版本日志的唯一来源。格式和检查归
`scripts/release-notes.ts` 所有。

## 写日志

发版前，描述上一个正式版 tag 到准备打包的提交之间用户能感知的改动。可以用本地 AI 起草，由人改好后提普通 PR。打 tag 前核对
该 PR 之后合并的提交，补上漏写的内容，tag 打在核对过的提交上。

```json
{
  "schema": 1,
  "version": "0.7.0",
  "date": "2026-12-10",
  "entries": [{ "category": "feature", "zh-CN": "……", "en-US": "…" }]
}
```

| 字段                                 | 规则                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------- |
| `schema`                             | `1`                                                                       |
| `version`                            | 不带 `v` 的正式版本号，等于文件名                                         |
| `date`                               | 计划发布日期，`YYYY-MM-DD`，可能与实际发布日不同                          |
| `entries`                            | 1 到 50 条                                                                |
| `entries[].category`                 | `important`、`feature`、`improvement`、`fix` 之一                         |
| `entries[].zh-CN`、`entries[].en-US` | 都必填，单行纯文本，最多 500 个字符，不含控制字符、行分隔符和双向格式字符 |

不接受其他字段；日志不列来源 PR 和提交范围。

## 检查

工具脚本的测试会校验仓库里的每份日志，只改 `release-notes/` 的 PR 也会触发。

`task package:desktop -- --tag <版本>` 和发布工作流只在满足下列条件时构建：

- `release-notes/` 里有该正式版本的日志。`v0.7.0`、`v0.7.0-rc.1` 和 `0.7.0+suffix` 都要求 `0.7.0.json`。
- 每份日志都合格，不只是本版本的那份。
- `release-notes/` 与检出的提交一致：没有修改、删除、未跟踪或被忽略的文件，并且源码是 git 检出。其他位置的改动不影响。

不带 `--tag` 的打包跳过这些检查。

## 展示

Desktop 前端构建时注入检出里的全部日志；应用展示时不读文件、不联网。不带 `--tag` 的构建遇到不合格的日志会隐藏全部日志，
不会失败。文字始终按纯文本显示，跟随界面语言，按版本倒序，不显示高于当前正式版本的日志（`0.7.0-rc.1` 显示到 `0.7.0`）。

- **设置 → 更新日志**列出历史。
- **一张可关闭的卡片**在更新后出现一次。它列出高于本机已提示过的最高版本的全部版本，然后记下当前版本。降级、没有本版本日志的
  构建和全新安装不显示卡片；其中只有全新安装会记下版本。

没有记录时，用 `is_new_installation` 区分全新安装和升级：本次启动打开的数据库没有已应用的迁移时为真。没有记录的升级列出全部
适用的版本。

### 更新之前

`latest.json` 在 `ora_release_notes: { schema, versions }` 里带上不高于所发版本的最近 10 个版本的日志；标准的 `notes` 必须保持字符串，
否则更新器插件解析不了整份清单。只写入已知字段。所发版本没有日志、或任一文件不合格时，发布 job 失败。

清单没有签名，又由所有已安装的客户端读取，所以 Desktop 把日志当作不可信的协议，与检查更新分开读。未知字段忽略；未知 `schema`、
内容不合规则、超过 10 个版本或某版超过 50 条时隐藏全部日志并在日志里记录原因，检查、下载和安装不变。同一 `schema` 下，这里写入的
上限不能高于任何已发布客户端的上限。

设置 → 更新日志在历史上方显示可更新的版本、高于当前正式版本且不高于目标版本的日志，以及安装操作；安装会重启应用，所以仍要
确认一次。清单里的日志不进历史，也不保存。需要手动更新的安装能看到日志，
没有安装操作。
